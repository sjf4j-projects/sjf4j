are retained for diagnosis, not cross-CPU regression claims.

## Findings

- **POJO List at 100,000 rows:** Compiled is **14.24×** faster than Spring,
  **6.92×** faster than MyBatis Auto and **9.95×** faster than MyBatis Explicit.
- **Record List:** Compiled reaches **117.47×** at 1,000 rows and **91.99×** at
  100,000 rows against Spring's `DataClassRowMapper` on this fixture.
- **Map List at 100,000 rows:** **2.36×** against Spring and **4.01×** against
  MyBatis Explicit. Map results are more fork-sensitive than POJO and Record.
- **List and Row:** The prepared-row execution path remains close in both modes
  at 1,000 rows; no additional per-row allocation is evident.
- **Allocation at 100,000 rows:** POJO and Record Compiled List allocate about
  **22.9 MB/op**, Map List about **76.1 MB/op**. The Spring / Compiled allocation
  ratios are **12.66×**, **51.64×** and **1.73×**, respectively.

The previous accepted Xeon 6975P-C report remains a separate baseline.
The CPU and JDK patch differ, so differences against it do not establish
regressions or code-level improvements. An earlier [EPYC 7763 run](https://github.com/sjf4j-projects/sjf4j/actions/runs/43263645344)
is useful historical context, but predates prepared List row-mapper reuse and
is not a controlled A/B. Do not attribute all observed differences to that change.

## Scope

SQL execution, connection acquisition and network I/O are outside measurement.
Spring's Map has case-insensitive lookup; the other Map implementations differ
internally. MyBatis Cursor materializes a full List. Invocation setup/teardown
can affect one-row precision and allocation accounting. Raw JMH JSON and
runner metadata are retained in the linked Actions artifact (subject to expiry).

For workload, code examples, commands and current CPU index, see
[JDBC Mapping performance baseline](../jdbc-mapping.md).
