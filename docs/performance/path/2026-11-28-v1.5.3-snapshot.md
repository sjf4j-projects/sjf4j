# Bookstore JSONPath Benchmark — SJF4J v1.5.3-SNAPSHOT — 2026-11-28

Versioned performance snapshot. Preserve this report unchanged when recording later runs.

## Provenance

- **Run:** [Path Full Benchmark #46130448820](https://github.com/sjf4j-projects/sjf4j/actions/runs/46130448820) — successful Full / Map, JsonNode, POJO, and Parse jobs.
- **Source commit:** [`857c5872ddfc56679a3cf3f635202ac2b90e7b46`](https://github.com/sjf4j-projects/sjf4j/commit/857c5872ddfc56679a3cf3f635202ac2b90e7b46) (PR #480).
- **Comparison dependency versions:** Jayway JsonPath `3.0.0`; Jackson2 Databind `2.22.3`; JMH `1.37`.
- **Date:** 2026-11-28 UTC.
- **JDK / OS:** Temurin OpenJDK 25.0.5.1+2, Ubuntu 24.04, x86-64 GitHub-hosted runners.
- **CPU:** Map/JsonNode/Parse — Intel Xeon 6975P-C; POJO — AMD EPYC 7763 (4 vCPUs per runner).
- **JMH:** AverageTime, 1 thread, 3 independent forks, 5 × 1s warmup and 5 × 1s measurement, `-prof gc`. Groups ran in separate jobs.
- **Inputs:** deterministic Bookstore object: **1,021 / 10,267 / 102,395 bytes** (12 / 123 / 1,229 books), ~30% Filter matches.
- **Semantics:** query input objects and paths are prepared outside timed operations, with setup-time result-equivalence checks. The Parse group measures only expression compilation.
- **Completed:** 45 Map + 45 JsonNode + 30 POJO + 14 Parse = **134 JMH cases**.
- **Raw artifacts:** [combined and per-shape JMH JSON, logs, and runner metadata](https://github.com/sjf4j-projects/sjf4j/actions/runs/46130448820#artifacts) (subject to GitHub retention).

**All query latency values below are Best 2 Mean in ns/op (lower is better).** Average the five iterations within each fork, exclude the slowest fork independently for each case, then average the remaining two. Ratios use unrounded latency. Untrimmed JMH score/error and B/op are not Best 2 Mean uncertainty estimates.

## Interpretation

At the tested 1/10/100KB sizes, SJF4J Runtime was faster than Jayway in **30 of 30** comparable Map and JsonNode query cases. CompiledNavigator was faster than Runtime in **45 of 45** comparable Map, JsonNode, and POJO query cases.

All **134 JMH cases** completed: 45 Map, 45 JsonNode, 30 POJO and 14 Parse. All five query types have CompiledNavigator implementations for all three data representations. Supported Filter predicates compile directly; Descendant traversal is generated without full-path runtime fallback. The Filter workload is numeric (`@.price > 10`); this run does not measure regex function execution.

These are exploratory hosted-runner measurements. Map, JsonNode and Parse used Intel Xeon 6975P-C; POJO used AMD EPYC 7763. Compare implementations within the same input type and runner job. The 1KB POJO compiled Filter has unstable fork means; its 13.79× ratio should not be treated as a stable speedup.

The previous published [2026-11-11 snapshot](2026-11-11-v1.5.0.md) used a cached FilterExpr predicate for compiled filters. It used AMD EPYC 7763 for Map/POJO/Parse and AMD EPYC 9V74 for JsonNode. Do not infer regressions or speedups from cross-CPU deltas. Even the same-CPU POJO comparison spans different JDK builds and changes to filter generation, so it is not a controlled A/B test.
