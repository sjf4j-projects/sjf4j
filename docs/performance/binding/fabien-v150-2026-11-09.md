# Fabien Binding Full Benchmark — v1.5.0 — 2026-11-09

> Historical performance snapshot. All values below come from the completed [GitHub Actions Binding Full run #42581094035](https://github.com/sjf4j-projects/sjf4j/actions/runs/42581094035). Shared runners are exploratory, not a hardware-independent baseline.

**1,008 JMH cases · 7 backends · 1/10/100KB · Read/Write · Users/Clients · POJO/Map · 2 seeds.** Latency uses per-case **Best 2 Mean** and equal-weighted seeds; B/op uses untrimmed JMH allocation scores. All comparable tables retain **Native / Blackbird / Runtime / Compiled** in that order; — means no equivalent implementation.

## Conclusions by backend

### Jackson2

**Read:** The standout is Clients POJO at 100KB: Native **622.862**, Blackbird **592.055**, Runtime **199.988**, Compiled **175.102 µs/op**. Compiled is **3.56× faster than Native** and **3.38× faster than Blackbird**; Runtime already captures most of the gain, with Compiled adding another **1.14×**. At 100KB Users POJO, Compiled **148.947 µs/op** also improves on Blackbird **158.189 µs/op**. **Write:** Users POJO Compiled **110.857** versus Native **139.779 µs/op**; Clients POJO **187.020** versus **257.872 µs/op**. Map Read is close to Native and Map Write usually benefits mostly from Runtime, not additional compilation. **Allocation:** 100KB Clients POJO Read drops from Native **1,241,410** to Compiled **282,937 B/op** (**77.2% less**); Users POJO Write drops from **199,054** to **112,061 B/op**.

### Jackson3

**Read:** Clients POJO at 100KB: Native **772.862**, Blackbird **754.982**, Runtime **249.817**, Compiled **218.543 µs/op**. Compiled is **3.54× faster than Native**, **3.45× faster than Blackbird**, and **1.14× faster than Runtime**. Users POJO Read Compiled **194.044 µs/op** also beats Native **226.058** and Blackbird **222.663**. **Write:** 100KB Clients POJO improves from Native **340.871** to Compiled **265.962 µs/op**; Users POJO from **184.547** to **168.982 µs/op**. Map Read is near Native (sometimes slightly slower). **Allocation:** Clients POJO Read drops from **1,213,238** to **254,754 B/op** (**79.0% less**); Users POJO Write from **199,069** to **112,085 B/op**.

### Fastjson2

**Read:** Compiled brings POJO performance close to Native: 100KB Users POJO Native **63.783**, Runtime **89.261**, Compiled **65.893 µs/op**; Clients POJO Native **74.604**, Runtime **103.453**, Compiled **74.001 µs/op**. But **Map Read is a clear limitation**: 100KB Users Map Native **95.688** versus Compiled **106.571 µs/op** (Native is about **11.4% faster**, in latency terms), and Clients Map **114.147** versus **122.164 µs/op**. **Write:** Users POJO Native **53.039**, Compiled **53.399 µs/op**; Clients POJO **48.670** versus **49.454**, essentially native-level. **Allocation:** 100KB Clients POJO Read Native **255,213**, Compiled **254,605 B/op**; little allocation difference, while Users Map Read allocates **557,157** Native versus **570,106 B/op** Compiled.

### Gson

**Read:** 100KB Clients POJO Native **833.780**, Runtime **385.232**, Compiled **333.997 µs/op**, a **2.50×** improvement over Native; Users POJO Compiled **275.615** versus Native **324.607 µs/op**. **Write:** 100KB Users POJO Native **443.815**, Runtime **243.785**, Compiled **210.322 µs/op** (**2.11×** Native/Compiled). Clients POJO Compiled **275.900** versus Native **487.814 µs/op**. Map Write gains mainly through Runtime; Compiled is almost the same. **Allocation:** Clients POJO Read drops from Native **1,399,430** to Compiled **486,214 B/op** (**65.3% less**); Users POJO Write from **522,167** to **216,357 B/op** (**58.6% less**). The native Gson byte[] path uses String-to-UTF-8 conversion; results measure the same final byte[] contract, not identical serialization internals.

### JSON-P

No equivalent Native POJO/Map binder and no Blackbird implementation in this suite; both columns remain **—**. **Read:** 100KB Users POJO Runtime **356.928**, Compiled **322.115 µs/op** (**1.11×**); Clients POJO **491.747** versus **445.431 µs/op** (**1.10×**). **Write:** Users POJO **233.514** versus **190.743 µs/op** (**1.22×**); Clients POJO **300.859** versus **263.251 µs/op** (**1.14×**). Map Runtime and Compiled are effectively tied. **Allocation:** Users POJO Read is **519,956 / 520,399 B/op** (Runtime/Compiled); Users POJO Write is **317,176 B/op** for both. Code generation reduces execution time without materially reducing allocation.

### Simple

No external Native binder or Blackbird implementation. **Read:** 100KB Users POJO Runtime **405.426**, Compiled **343.667 µs/op** (**1.18×**); Clients POJO **408.852** versus **385.367 µs/op** (**1.06×**). **Write:** Users POJO Runtime **501.776**, Compiled **478.316 µs/op** (**1.05×**); Clients POJO **486.467** versus **457.020 µs/op** (**1.06×**). Map performance is approximately the same with or without compilation. **Allocation:** Users POJO Read **504,235 / 504,234 B/op**, Write **216,168 / 216,167 B/op**; differences are negligible. Several Simple Read cases have fork spread above 15%, so small advantages should be rechecked.

### SnakeYAML

The Native implementation is a SnakeYAML POJO/Map binder with equivalent UUID/time support; there is no Blackbird. **Read:** 100KB Clients POJO Native **6,704.549**, Runtime **4,539.373**, Compiled **4,380.591 µs/op** (**1.53×** Native/Compiled). **Write:** 100KB Users POJO Native **9,208.703**, Runtime **4,141.737**, Compiled **4,108.626 µs/op** (**2.24×** Native/Compiled); Map Write shows similar Native-to-Runtime gains. Most of the advantage is already in Runtime, not additional compilation. **Allocation:** Clients POJO Read drops from Native **9,134,260** to Compiled **6,143,591 B/op** (**32.7% less**); Users POJO Write from **6,824,854** to **5,866,153 B/op** (**14.0% less**). YAML and JSON backend latencies must not be treated as equivalent-format comparisons.

## Provenance and metric definitions

- [GitHub Actions Binding Full run #42581094035](https://github.com/sjf4j-projects/sjf4j/actions/runs/42581094035), workflow_dispatch on `main`, source commit `c17ac35593e7294078bd38f449b06a7295776f05`. Seven backend jobs and the bundling job succeeded.
- [Original JMH JSON, per-fork iterations, allocation and runner metadata](https://github.com/sjf4j-projects/sjf4j/actions/runs/42581094035/artifacts/13675482490). GitHub artifacts may expire.
- **1,008 exact JMH cases:** 7 backends, Read/Write, Users/Clients, POJO/Map, sizes 1/10/100KB, seeds 12345 and 324, applicable implementations Native / Blackbird / Runtime / Compiled.
- **Temurin JDK 25, JMH AverageTime**, one thread, 3 independent forks, 5 × 1s warmup and 5 × 1s measurement; GC allocation profiler. Figures are **µs/op**, lower is better.
- **Latency Best 2 Mean:** average 5 measurement iterations within each fork; select the 2 smallest fork means **for each exact case (including implementation and seed)**. Then average seed 12345 and seed 324 equally, without pooling forks across implementations.
- **Memory B/op:** arithmetic mean of the **untrimmed** `gc.alloc.rate.norm.score` for the two seeds; do not assign the latency Best 2 selection or JMH score error to allocations.
- A ratio such as **Native / Compiled = 3.56×** measures speedup, not a separate observation. Values in the tables are rounded; ratios use unrounded data. **—** means a comparison is not available or equivalent.
- **JSON-P** has no directly equivalent native Java POJO/Map binder in this suite; **Simple** has no external native implementation. Blackbird is only present for Jackson2/3. These omissions are intentional, not failures.
- **Read** converts a UTF-8 byte[] to a new POJO/Map. **Write** serializes a POJO/Map to a newly produced byte[]. Fixture generation, backend selection and semantic verification are outside timed operations. Comparisons are meaningful **within a backend**; backend jobs use different GitHub runner CPUs. YAML and JSON are separate formats.

## Scope limitations

These are results for the provided Fabien fixtures, not general throughput guarantees.
